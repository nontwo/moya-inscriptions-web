# T05.4-A Catalog Import Contract & Workbook Specification

- 状态：Owner Review Approved with canonical-hash clarification（2026-08-12）
- Import Contract Version：`catalog-import/v1`
- Baseline：`origin/integration/mvp@b1934541c64c3cddfd513838e5aad223f06dce38`
- Governance：ADR 0006 Accepted

## 1. 目标与边界

本规范冻结长期Catalog bulk input的canonical representation、Owner
workbook、CSV、dry-run与Import Batch contract。PostgreSQL仍是production runtime
source of truth；XLSX是Owner/Editor working format；CSV/canonical rows是bulk
interchange boundary。

本阶段不实现XLSX/CSV文件parser、diff、duplicate detection
algorithm、apply、staging、database
migration、Admin、publication、Media、UGC或Evidence
Domain。仓库只保存schema、specification、测试和无真实数据的安全空白template。

```text
XLSX / CSV bundle
→ version check
→ parsed table rows                       [future]
→ canonical rows + shared validation
→ identity conflict / duplicate analysis [future]
→ diff + persistence blockers            [future]
→ dry-run
→ approval bound to canonical hashes
→ apply                                  [future, currently blocked]
→ PostgreSQL
```

## 2. Existing architecture findings

- `CatalogKind`的唯一runtime source是`@moya/contracts`中的两值Zod enum。
- 当前`catalog_entries`可承载CatalogId、kind、title、summary、description和periodLabel；
  `catalog_aliases`只有alias文本与position；`catalog_source_citations`是curated
  Public citation，不是raw provenance。
- 当前没有SourceRecord、alias type、region/location、Import
  Batch、audit或publication persistence。
- Public DTO/OpenAPI已严格拒绝SourceId、raw
  source、owner/review、storage与migration字段。
- Raw dataset importer allowlist仍为空；T05.4-A不开放任何workspace。

因此本阶段不需要migration，也不得把无法安全承载的Owner字段强塞入现有read model。

## 3. Versioned canonical import model

Internal contract只从`@moya/contracts/internal/catalog-import`导出。Public
root、OpenAPI和Frontend不能导入该subpath。

### 3.1 Contract version

v1唯一合法值为`catalog-import/v1`。Canonical
envelope、dry-run、approval与batch都必须显式携带该值；missing/unknown
version在row validation之前失败。Workbook在
`99_Instructions`保存machine-readable metadata；CSV bundle必须包含单行
`00_manifest.csv`。不得从文件名或sheet布局猜测version。

### 3.2 Identity

```text
CatalogImportId != SourceId
CatalogImportId != CatalogId
SourceId != CatalogId
CatalogId != future SiteId
```

- `catalogImportId`：同一workbook/batch内的临时关联键；不持久化，不是第四套domain
  ID。
- `sourceId`：source-record identity。`01_Catalog`中的值是primary source
  identity。
- `catalogId`：optional；blank表示create candidate，VALUE表示update target。
- `catalogId`和已经建立的SourceId→CatalogId linkage不能通过普通import改写。

### 3.3 Canonical rows

`CanonicalCatalogImportEnvelope`包含`catalogRows`、`aliasRows`与
`provenanceRows`。v1没有position/order字段，因此三组row
collection的提交顺序只属于XLSX/CSV presentation，不属于domain
semantics；单纯重新排列worksheet或CSV rows不得改变`canonicalInputSha256`。

Hash representation的算法冻结为：

1. 先验证明确的`importContractVersion`，再完整验证canonical envelope、row
   contents与跨row uniqueness/reference invariants；无效输入没有canonical hash。
2. 不修改validated input，复制三组数组并分别升序排序：
   - `catalogRows`：tuple `[catalogImportId]`
   - `aliasRows`：tuple `[catalogImportId, alias]`
   - `provenanceRows`：tuple `[catalogImportId, sourceId]`
3. Tuple逐项比较；每项采用ECMAScript String relational
   comparison的locale-independent UTF-16 code-unit lexicographic
   order。不使用`localeCompare`，不做Unicode normalization、case
   folding、trim或其他值转换。现有uniqueness规则保证每个sort
   key在所属collection内唯一。Canonical hash输入的所有string必须是well-formed
   UTF-16；unpaired surrogate失败而不是被替换。
4. 保留row内全部validated values、tagged field
   states与`importContractVersion`，然后按RFC 8785-compatible object-key
   ordering生成canonical JSON。
5. 对canonical JSON的UTF-8 bytes计算SHA-256，输出64位lowercase hexadecimal。

Golden vector固定为
`bb16bfca66165acccafbdf63134f26ea480184d846b26491d29619a3ba2bae1b`；测试同时证明三组rows重新排序保持相同serialized
representation，而任一row value/state或membership变化都会改变hash。

Catalog row required：

- `catalogImportId`
- `sourceId`
- `title`
- `catalogKind`：仅`inscription | calligraphy`

Catalog row optional：

- `catalogId`
- tagged dynasty/date/region/current-location/custodian/description fields
- `ownerNote`

Alias row：`catalogImportId + alias + aliasType`，其中`aliasType`必填且仅允许
`alternate | historical`。`normalized_search`不是alias
type；搜索规范化是未来可重建的derived representation。

Provenance
row：`catalogImportId + sourceId + sourceTitle? + sourceTypeRaw? + sourceUrl? + sourceNote?`。`sourceTypeRaw`是raw
descriptive text，不是taxonomy、evidence quality、authority或publication
decision。

## 4. Field and persistence matrix

| Field/concept                    | Required    | Persistence disposition | Protection          | v1 apply behavior                        |
| -------------------------------- | ----------- | ----------------------- | ------------------- | ---------------------------------------- |
| catalogImportId                  | yes         | RAW_ONLY / batch-local  | identity validation | never domain-persisted                   |
| sourceId                         | yes         | RAW_ONLY                | identity invariant  | requires future SourceRecord persistence |
| catalogId                        | update only | SUPPORTED_NOW           | identity invariant  | target only; never mutated               |
| title                            | yes         | SUPPORTED_NOW           | Level B             | critical diff + field approval           |
| catalogKind                      | yes         | SUPPORTED_NOW           | Level A             | structural diff + field approval         |
| dynasty/dateText                 | no          | DEFERRED_PERSISTENCE    | Level B             | apply blocker when supplied              |
| province/prefecture/county       | no          | DEFERRED_PERSISTENCE    | Level B             | apply blocker when supplied              |
| currentLocation/currentCustodian | no          | DEFERRED_PERSISTENCE    | Level B             | apply blocker when supplied              |
| description                      | no          | SUPPORTED_NOW           | Level C             | diff; CLEAR requires field approval      |
| ownerNote                        | no          | RAW_ONLY                | Level C             | never Public/Catalog persistence         |
| alias + aliasType                | child row   | DEFERRED_PERSISTENCE    | Level B             | entire row blocked until type persists   |
| provenance metadata              | child row   | RAW_ONLY                | Level B             | blocked until SourceRecord persistence   |

`summary`、`periodLabel`和curated Public citations虽已存在于read
model，但不属于v1 input；import必须保持其现值。Publication lifecycle、location
history、generated review、normalized source taxonomy、field
evidence与media属于FUTURE。

## 5. Blank, knowledge state and clear

Canonical tagged state是：

- `VALUE { value }`
- `UNSUPPLIED`
- `UNKNOWN`
- `NOT_APPLICABLE`
- `CLEAR`

XLSX/CSV使用paired value/state columns。规则：

| Value cell | State cell          | Canonical result |
| ---------- | ------------------- | ---------------- |
| nonblank   | blank or VALUE      | VALUE            |
| blank      | blank or UNSUPPLIED | UNSUPPLIED       |
| blank      | UNKNOWN             | UNKNOWN          |
| blank      | NOT_APPLICABLE      | NOT_APPLICABLE   |
| blank      | CLEAR               | CLEAR            |
| nonblank   | any non-VALUE state | validation error |
| blank      | VALUE               | validation error |

Required/identity fields没有state column。Factual nullable
fields允许全部state；description只允许VALUE、UNSUPPLIED与CLEAR。Owner
note和append-only provenance不提供destructive state。普通blank永远不是delete。

任何非UNSUPPLIED的DEFERRED_PERSISTENCE或RAW_ONLY内容必须出现在dry-run；如果没有durable
preservation，apply必须返回`DEFERRED_FIELD_NOT_PRESERVED`。Approval不能授权silent
loss。

## 6. Identity conflict, critical change and approval

`IDENTITY_CONFLICT`与`CRITICAL_CHANGE`永久分开：

- Identity conflict：CatalogId mismatch/rebinding、update target不存在、SourceId
  rebound或existing SourceId→CatalogId
  association冲突。它不可approval，必须阻断batch。
- Critical
  change：CatalogKind、title、temporal、region、location、custodian、alias或provenance
  metadata等非identity事实变化。它可审核，但Level A/B必须field-level approval。
- Level C ordinary change可由batch approval覆盖；任何Level的CLEAR都要field-level
  approval。

Approval必须绑定：

- `importContractVersion`
- `canonicalInputSha256`
- `dryRunResultSha256`

`canonicalInputSha256`是validated canonical
envelope先按3.3的稳定业务键排序，再经UTF-8 RFC 8785-compatible canonical
JSON序列化后的SHA-256。XLSX styling、ZIP metadata、worksheet/CSV row order、CSV
BOM/quoting/newline不参与authorization hash。
`sourceArtifactSha256`只用于原文件audit。任何canonical semantic
input或dry-run变化都会使approval失效；只重排行不会使approval失效。

## 7. SourceId uniqueness and mirroring

- `01_Catalog.catalogImportId`与`01_Catalog.sourceId`各自在batch内全局唯一。
- supplied `catalogId`最多出现在一条Catalog row；额外来源进入`03_Provenance`。
- `03_Provenance`的`(catalogImportId, sourceId)`唯一；SourceId在同一batch只能解析到一个catalogImportId。
- Provenance可以在相同catalogImportId下镜像primary
  SourceId以补充metadata；这是同一SourceRecord的扩展，不是新source。镜像optional，重复pair是validation
  error。
- Additional provenance SourceId不得等于另一个Catalog row的primary SourceId。
- 跨batch遇到相同SourceId→CatalogId可以update/unchanged；不同linkage为non-approvable
  identity conflict。

## 8. Duplicate policy

Duplicate SourceId或identity mismatch是validation/identity
conflict，不是similarity candidate。Title
normalization、region、custodian、provenance与existing IDs只能产生
`DUPLICATE_CANDIDATE`和signals。Reviewer disposition仅有：

- `SAME_ENTITY_CANDIDATE`
- `DIFFERENT_ENTITY_CANDIDATE`
- `UNRESOLVED`

Candidate不能自动merge、重写CatalogId或解除apply
blocker。真正merge属于未来Owner/Admin workflow。

## 9. Workbook specification

Safe template：`catalog-import-v1-template.xlsx`，且只有四张sheet：

1. `01_Catalog`
2. `02_Aliases`
3. `03_Provenance`
4. `99_Instructions`

Header顺序由executable `CATALOG_IMPORT_WORKBOOK_SPEC`冻结。Identity列使用text
format；categorical/state列使用data validation；data
sheets提供filters。冻结header是workbook
contract的目标行为，但本次使用的artifact-tool v2.8.6虽接受freeze
API，导出OOXML时没有写入pane；交付检查明确记录这个presentation
limitation，且未来重新生成时必须复验。Template没有production或synthetic Catalog
rows，不包含objectKey、storage path、SQL、credentials、rights internal
notes、ORM或migration metadata。

`99_Instructions`包含version
metadata、中文录入说明、合法enum、state规则、persistence matrix、apply
blockers和“successful import != automatic publication”。Workbook是human working
format，不是domain/schema source of truth。

## 10. CSV specification

CSV bundle文件：

- `00_manifest.csv`
- `catalog.csv`
- `aliases.csv`
- `provenance.csv`

Input接受UTF-8 optional BOM及单一LF或CRLF newline style；mixed
newlines、duplicate headers、unknown headers或case
variation均失败。Parser可以按header定位输入列，但canonical
serializer固定contract顺序，使用UTF-8 no BOM、LF、RFC 4180 quoting与final
newline。Empty/state semantics与XLSX完全相同，两个format必须进入同一canonical
schema与hash逻辑。

## 11. Alias and provenance apply gates

`catalog_aliases`不能保存required aliasType，因此不得只写alias
text并丢失type；任意Alias row在真正apply前必须解决domain
persistence，当前返回`ALIAS_TYPE_STORAGE_REQUIRED`。

Raw provenance不能写进curated
`catalog_source_citations`；真正apply前必须建立SourceRecord/ provenance
persistence，当前返回`PROVENANCE_STORAGE_REQUIRED`。仅在batch audit中保留raw
input是必要条件，但不能替代这两个domain persistence gap。

## 12. Import Batch and audit contract

Import Batch记录batchId、version、input format、optional artifact
hash、canonical input hash、createdAt、per-table row
counts、dry-run、approval与optional appliedAt。Dry-run包含result
counts、findings、duplicate candidates、apply blockers和result hash。

Batch
phase是独立enum：`RECEIVED | VALIDATED | DRY_RUN_COMPLETE | AWAITING_APPROVAL | APPROVED | APPLY_BLOCKED | APPLIED | REJECTED`。它不替代dry-run
state或approval state；schema同时验证batch、dry-run与approval的row
counts、version/hash binding、finding approval及appliedAt invariant。

Apply前置条件：dry-run PASSED、approval
APPROVED且三项binding一致、零error、零identity conflict、零unresolved
blocker。Batch phase、dry-run、approval、Catalog lifecycle与publication
state不得复用单一通用status。

## 13. Public, security and media boundary

- Internal import subpath不得进入Web/Admin/UI/Public API或OpenAPI。
- Owner notes、raw provenance、batch/approval/review、identity
  conflicts和internal persistence metadata永不进入Public DTO。
- v1不接收local file path、objectKey、CDN URL、storage provider
  detail或图片本体。
- Import成功不改变publication；v1不定义publicationIntent。
- Official Catalog与UGC继续隔离。

## 14. Implementation and test checkpoint

T05.4-A实现shared schema、tabular-to-canonical field semantics、deterministic
canonical serialization、safe template与contract/architecture/template
tests。后续阶段必须另行实现并验证：

- XLSX/CSV parsers及跨format canonical/hash equivalence；
- identity lookup、duplicate signals、diff与dry-run result hashing；
- durable Import Batch/raw preservation；
- deferred Catalog facts、aliasType与SourceRecord migrations；
- transactional apply、rollback、idempotence与Owner/Admin identity-resolution
  workflow。

Owner已接受本次artifact-tool导出缺少frozen pane，不构成T05.4-A
blocker；未来重新生成template时复验即可。Owner也批准当前deferred persistence
strategy，但不得为T05.4-A增加migration。正式Apply前必须经过独立persistence-gap
closure
checkpoint，无损解决temporal/region/location/custodian、aliasType、SourceRecord/provenance与durable
Import Batch audit。Identity
conflict在v1继续不可approval、不可Apply；完整resolution
workflow暂不建设，未来按真实案例独立实施。在这些checkpoint完成前，production
apply保持blocked。
