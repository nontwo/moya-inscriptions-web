# P2-03 Search 平台兼容性评估

- 状态：evaluation-only；公开文档核对，不是部署或迁移验收。
- 核对日期：2026-09-07。
- 实验版本：PostgreSQL 18.4。此版本仅用于本任务隔离实验，不是现有服务升级建议。
- 当前自管 CVM：未连接、未检查操作系统、数据库版本、扩展、容量或权限，未安装任何软件。
- 未来托管目标：TencentDB for PostgreSQL；没有选定地域、规格、内核或实例。

## 结论与证据等级

现有 PostgreSQL 内完成检索，在未来迁至 TencentDB
PostgreSQL 时有较少的进程和同步职责，但兼容性仍须按实际目标版本验证。`pg_trgm`
已有托管扩展矩阵依据；条件性 `pg_bigm` 实验不能被写成 TencentDB PostgreSQL
18 已支持。Meilisearch CE 是独立进程对照，数据库托管不包含该进程的部署和运维。

本文采用三种证据等级：**文档事实**、**条件性推论**、**未验证**。本地实验结果由本任务的 benchmark 证据单独记录；本文不重复或推导任何运行结果。腾讯云不同站点页面存在更新日期差异，因此公开支持矩阵只能作为候选依据，不能代替目标实例能力查询和隔离验收。

## 版本与扩展边界

腾讯云中国站产品功能表已列 PostgreSQL
18；官方中文国际站数据库代理版本说明进一步列出 `v18.4_r1.10`
等内核要求。这证明官方文档中存在 PostgreSQL 18/18.4 系列，不证明社区 PostgreSQL
18.4 与腾讯云内核二进制、补丁、参数和执行计划相同，也不证明特定地域、规格或既有实例已提供该版本。来源：[产品功能列表](https://cloud.tencent.com/document/product/409/127570)、
[数据库代理版本更新动态](https://intl.cloud.tencent.com/zh/document/product/409/82545)。

| 能力或依赖                    | 隔离 PostgreSQL 18.4 的评估对象                                                | TencentDB PostgreSQL 的公开依据与条件                                                                                                          | 当前自管 CVM |
| ----------------------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| 标题/已批准别名 exact、B-tree | 现有字段的等值查询和索引；不增加领域语义                                       | 作为 PostgreSQL 内置 SQL/索引能力的迁移候选。目标 collation、operator class、索引定义、权限与执行计划仍待验证；平台版本声明不等于排序/性能验收 | 未验证       |
| 前缀、包含查询                | 分开记录等值、前缀和任意位置包含的实际计划与成本                               | 不能从平台“支持 PostgreSQL”推导所有模式都走 B-tree；需按目标内核重复相同查询与索引验收                                                         | 未验证       |
| `pg_trgm`                     | 扩展 GIN 检索与短词退化的实际测量                                              | 官方中文国际站矩阵在 v14–v18 列 `1.6`；仍需核对目标实例可安装版本及实际已安装版本                                                              | 未验证       |
| 内置 FTS                      | 固定 parser/configuration 的 `tsvector`/`tsquery` 对照，包括连续中文短词的漏检 | 内置 FTS 与中文分词扩展是不同依赖。没有将“可执行 FTS SQL”作为中文召回通过；目标配置、词典、中文 token 和正确结果位置仍须验证                   | 未验证       |
| 条件性 `pg_bigm`              | 仅在基线实际短词缺口触发后，才按批准范围实验                                   | 同一国际站矩阵 v10–v17 列 `1.2`，v18 为 `-`。本次文档核对没有取得 v18 支持证据；本地编译或查询通过不能填补该空白                               | 未验证       |

扩展版本事实来源：[支持插件版本概览（官方中文国际站，页面更新于 2026-07-08）](https://intl.cloud.tencent.com/zh/document/product/409/47734)。中国站插件创建说明明确要求按大版本查文档，并以
`pg_available_extensions`
查询实例能力。本轮读取到的中国站镜像版插件矩阵更新于 2025-07-29、止于 v17，不能据此推断 v18。来源：[创建插件说明](https://cloud.tencent.cn/document/product/409/121744)、
[中国站插件矩阵镜像](https://cloud.tencent.cn/document/product/409/75121)。

`pg_bigm`
的托管差异是后续方案选择条件：如果实验结果使它成为必要依赖，正式决定前必须确认目标托管版本支持，或明确保留自管部署。不得为了绕开此差异自行降级/升级数据库、新增托管实例，或把其他扩展全部加入实验。PGroonga、zhparser 不在本文件扩展评估范围。

## 自管 CVM 与托管数据库的职责差异

| 事项              | 自管 CVM 上的 PostgreSQL / Meilisearch CE                                      | TencentDB PostgreSQL 加外部 Meilisearch CE                                      |
| ----------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| 运行环境          | CVM 提供操作系统和计算资源；软件、二进制架构兼容性、进程隔离与容量由项目验证   | 托管数据库版本和扩展受产品能力约束；Meilisearch CE 仍须在另一个获批计算环境运行 |
| PostgreSQL 内检索 | 查询、可重建检索副本与索引可在同一数据库事务边界内维护；具体写入方案待批准     | 相同设计仍需核对托管权限、参数、扩展和迁移能力                                  |
| 独立引擎          | 增加进程、索引副本、持久化、更新任务及恢复职责；与数据库同机时也须计入资源竞争 | 这些职责不会因 PostgreSQL 托管而消失，并增加数据库与引擎之间的网络和同步验收    |
| OpenCC            | 作为后端/实验工具的依赖，不在未获批准的数据库服务内安装                        | 不要求托管数据库加载 OpenCC；由受控后端对查询和可重建检索副本使用固定配置       |
| 权限边界          | 自管权限是否足够、现有服务是否允许变更均未检查                                 | 托管账号不是主机管理权限，不能据此假设能够安装或启动独立引擎                    |

上述运行职责是本任务的条件性设计推论。腾讯云官方 CVM 概述说明实例包含 CPU、内存、操作系统、网络和磁盘；TencentDB 账号文档则明确未开放
`superuser` 属性以及
`pg_execute_server_program`、`pg_read_server_files`、`pg_write_server_files`
角色。因此不能把数据库扩展创建权限当作在数据库主机运行 Meilisearch
CE 的授权或能力。来源：[CVM 概述](https://intl.cloud.tencent.com/zh/document/product/213/495?lang=zh)、
[TencentDB 账号操作指引](https://cloud.tencent.com/document/product/409/107909)。

## 正式采用前的最小平台验收

以下是将来获得目标访问与操作授权后的验收条件，本轮未执行，也不要求现在采购资源：

1. 用受控程序只记录必要的版本、架构、collation 和扩展能力状态；不输出地址、账号、凭据、连接串或配置全文。分别核对社区版本、厂商内核版本和扩展版本。
2. 对同一获批字段白名单、固定 normalization 配置和 Golden Query
   Set，重跑 exact、前缀、包含、中文短词、正文、零结果与可见性边界，核对正确位置和执行计划。
3. 在目标资源限额下重跑查询耗时、空闲/峰值内存、索引大小、构建和增量更新成本。本地 PostgreSQL
   18.4 与 Meilisearch CE 的数字仅描述本地实验环境。
4. 若依赖扩展，先查询实际可用/已安装版本与必需参数；仅对授权的目标按审阅后的方案创建。官方说明指出部分扩展参数变更会重启实例，不能在已验收服务上试装或试改参数。
5. 若选择独立引擎，验收更新任务完成、失败重试、全量重建、删除和权限收紧的生效时间，并验证受控后端能阻止过期索引条目泄露不可见内容；数据库备份成功不等于搜索副本恢复通过。

插件能力查询和参数变更依据：[创建插件说明](https://cloud.tencent.cn/document/product/409/121744)。本文件不改变现有数据库、Catalog 原文或身份、MediaId、导入流程、前端行为及部署配置。
